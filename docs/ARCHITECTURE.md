# Hyperblaze Architecture

## Overview

Hyperblaze is built as a **4-crate Cargo workspace** with clear separation of concerns:

```
hyperblaze/
├── crates/
│   ├── hb-core/     # Core runtime (config, hashing, errors, platform)
│   ├── hb-graph/    # HyperGraph async incremental computation engine
│   ├── hb-exec/     # Action execution (process runner, disk cache)
│   └── hb-cli/      # CLI binary (clap commands)
├── Cargo.toml       # Workspace root
└── HYPERBLAZE.toml  # Project config (auto-generated by `hyperblaze init`)
```

## HyperGraph Engine

The **HyperGraph** is the heart of Hyperblaze -- an async, lock-free, incremental computation engine. It is functionally equivalent to:

- **Bazel's Skyframe** (Java, restart-based)
- **Buck2's DICE** (Rust, async-based)

### Comparison

| Feature | Skyframe (Bazel) | DICE (Buck2) | HyperGraph (Hyperblaze) |
|---------|-----------------|-------------|------------------------|
| Language | Java | Rust | Rust |
| Concurrency | ConcurrentHashMap + locks | DashMap | DashMap (lock-free) |
| Dependency handling | Return null, restart | Async suspension | Async suspension |
| Graph type | Static phases | Single unified | Single unified |
| Memory model | JVM heap (GC) | Native (zero-copy) | Native (zero-copy) |
| Invalidation | Version-based + dirty | Version-based + early cutoff | Version-based + early cutoff |

### Core Abstractions

```
NodeKey ----------> ComputeFn ----------> NodeValue
(FunctionType       (async fn)            (type-erased,
 + argument)         |                     Arc-wrapped)
                     |
                     v
              ctx.require(dep_key).await
              +---------------------------+
              | SUSPENDS the function     |
              | (yields thread to tokio)  |
              | RESUMES when dep is ready |
              | NO restart, NO wasted     |
              | computation               |
              +---------------------------+
```

#### NodeKey
A `(FunctionType, argument)` pair uniquely identifying a computation. Pre-computed hash for O(1) lookups. Cheap to clone (String-backed).

#### NodeValue  
Type-erased result wrapped in `Arc<dyn Any + Send + Sync>`. Can hold any type -- file state, package definitions, action results.

#### NodeEntry
State machine for each computation node:
```
NeedsEvaluation --> InFlight --> Done(value)
       ^                            |
       |                            v (dependency changes)
       +---- Dirty(old_value) <-----+
```

Uses `tokio::sync::watch` channels for async notification -- waiters suspend instead of polling.

#### ComputeContext
Passed to compute functions. The key method is `require()`:
```rust
pub async fn require(&mut self, dep_key: NodeKey) -> HbResult<NodeValue>
```
This is the **no-restart protocol**: instead of returning null and being restarted (Skyframe), the function suspends via `await` and resumes exactly where it left off.

#### Evaluator
Parallel evaluator driving computation. Uses tokio's work-stealing runtime for automatic load balancing across CPU cores.

### Early Cutoff Optimization

Inspired by Buck2's DICE engine. When a node is recomputed and produces the same value (compared by BLAKE3 digest), invalidation stops propagating to reverse dependencies:

```
file.rs changes
    |
    v
FileState("/src/file.rs")  ->  DIRTY
    | (rdep)
    v
PackageLoad("//src")  ->  DIRTY  ->  recompute  ->  SAME VALUE  ->  STOP
    | (rdep)                                        (early cutoff)
    v
ConfiguredTarget("//src:lib")  ->  NOT invalidated (saved work!)
```

### Incremental Invalidation

When a file changes:
1. File watcher detects change via `notify` crate (cross-platform: inotify/FSEvents/ReadDirectoryChanges)
2. The file's `NodeEntry` is marked `Dirty`
3. Dirty propagates to all **reverse dependencies** (nodes that depend on this file)
4. **Early cutoff**: if a recomputed node produces the same value as before, propagation stops

## Execution Engine

### Action Model
An `Action` is a command to execute:
- Executable + arguments
- Declared input files (with BLAKE3 digests)
- Expected output files
- Environment variables
- Resource requirements (CPU, memory)

### Cache Key
The cache key is computed from:
```
cache_key = BLAKE3(input_digests || args || env_pairs)
```
This is **content-addressed** -- if inputs haven't changed, the cache key is identical regardless of timestamps.

### LocalRunner
Executes actions as OS processes via `tokio::process::Command`. Features:
- Async execution (doesn't block the runtime)
- `kill_on_drop` for cleanup on cancellation
- Output capture (stdout/stderr)
- Output file digest computation

### ActionCache
Sharded disk-based cache:
```
.hb-cache/
  ac/           # Action cache (key -> result JSON)
    ab/cd.json  # Sharded by first 2 hex chars of key
  cas/          # Content-addressable store (future)
    ef/gh       # Output files by digest
```

## Core Runtime

### Configuration
Single `HYPERBLAZE.toml` file with sections:
- `[project]` -- name, version
- `[build]` -- jobs, cache, output dir
- `[remote]` -- cache/exec URLs, TLS, instance name

### BLAKE3 Hashing
All content addressing uses BLAKE3:
- 3-5x faster than SHA-256
- Streaming API for large files
- 32-byte digests with hex encoding

### Platform Detection
Runtime detection of:
- OS (Linux, macOS, Windows)
- Architecture (x86_64, aarch64)
- CPU count
- Available memory
- Sandbox capability (Linux namespaces, macOS sandbox-exec)

### VFS (Virtual Filesystem)
File metadata cache using `(path -> mtime + digest)`:
- Only re-hashes when mtime changes
- Thread-safe via `DashMap`
- Glob pattern matching for source file discovery

### File Watcher
Cross-platform file watching using the `notify` crate:
- Recursive directory monitoring
- Event batching and deduplication
- Filters out build outputs (.hb-out, .hb-cache, .git, target)
- Feeds changes into HyperGraph invalidation pipeline

## Design Principles

1. **No JVM** -- Native Rust binary, 0.4ms startup
2. **No restarts** -- Async suspension instead of Skyframe's null-return protocol
3. **No locks** -- DashMap for lock-free concurrent graph access
4. **No phases** -- Single unified graph (like DICE), not separate parse/analyze/execute phases
5. **No boilerplate** -- Auto-detect languages, infer dependencies
6. **No surprises** -- Beautiful error messages with miette diagnostics
